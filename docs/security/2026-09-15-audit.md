# Auditoría de seguridad — 2026-09-15

**Scope:** barrido completo (invocación `/security-audit` sin argumento) — `src/**`,
`package.json` / `pnpm-lock.yaml`, `docs/api/openapi.yaml`, `.gitignore`. No se

## Resumen ejecutivo

Proyecto muy pequeño y deliberadamente minimalista: un esqueleto Clean Architecture con
un único endpoint de ejemplo, `GET /api/health`, sin autenticación, sin base de datos y
sin manejo de uploads. El código propio de `src/` no presenta hallazgos de confianza
HIGH: la capa de dominio no lanza excepciones sin control, los DTOs nunca lanzan, los
errores nunca filtran stack trace al cliente (`HealthController.handleError`), no hay
serialización directa de entidades, no hay inyección (no hay SQL/NoSQL, `eval`, `exec`,
plantillas ni concatenación de queries), no hay secrets hardcodeados ni en `src/` ni en
`.env.template`, y `src/.env` está correctamente excluido de git (`.gitignore:14`,
verificado con `git check-ignore` y `git ls-files`).

Sí se encontró **1 hallazgo de confianza Alta y severidad Media**: la dependencia
transitiva `qs@6.15.3` (arrastrada por `express@5.2.1` vía `body-parser` y
directamente) tiene dos avisos de `pnpm audit` de severidad "moderate" — ambos de
denegación de servicio, explotables desde cualquier request sin autenticación porque
`express.json()`/`express.urlencoded()` están montados globalmente y el parseo ocurre
antes del ruteo. Ver `SEC-001`.

No hay hallazgos de confianza Media pendientes de verificación adicionales: los puntos
observados durante el reconocimiento (ausencia de CORS explícito, de cabeceras de
seguridad tipo Helmet, y de rate limiting) son de severidad Baja en el catálogo de
`docs/security.md` (defensa en profundidad, sin input atacante-controlado que las haga
explotables por sí solas dado que el único endpoint es público, de solo lectura y sin
datos sensibles) — se documentan como observaciones de superficie de ataque, no como
`SEC-NNN`, siguiendo la regla de no reportar confianza Baja.

## Superficie de ataque

- **Stack:** Node.js 20+, TypeScript (ESM `nodenext`), Express 5.2.1. Sin base de datos
  ni ORM. Gestor de paquetes `pnpm`.
- **Puntos de entrada HTTP:** un único router raíz (`src/presentation/routes.ts`) que
  monta `HealthRoutes` bajo `/api/health` (`src/presentation/health/routes.ts:17`), con
  un solo verbo (`GET`). No hay WebSockets ni workers. El contrato
  (`docs/api/openapi.yaml`) declara exactamente esa operación (`getHealth`, `x-status:
  live`) — sin deriva contra el código.
- **Middlewares globales:** `express.json()` y `express.urlencoded({ extended: true })`
  (`src/presentation/server.ts:31-32`), montados con `app.use(...)` antes del router, por
  lo que procesan el body de **cualquier** request entrante, exista o no la ruta.
- **Auth / sesiones:** ninguna. No hay JWT, cookies, ni `req.user`. Coherente con que el
  único endpoint es un health-check público por diseño.
- **Uploads / estáticos:** ninguno. No hay `multer`, `express.static` ni manejo de
  archivos en el árbol `src/`.
- **Validación de input:** `HealthQueryDto.create()` (`src/domain/dtos/health/health-query.dto.ts`)
  válida `?verbose` contra un enum estricto (`Validators.boolean`,
  `src/domain/validators.ts`) y nunca lanza; el controller responde `400` sin `try/catch`
  si el DTO falla.
- **Manejo de errores:** `HealthController.handleError` (`src/presentation/health/controller.ts:22-29`)
  distingue `CustomError` (usa su `statusCode`) de cualquier otro error (log server-side +
  `500` genérico sin stack trace) — coincide con el patrón seguro de
  `docs/security/../error-handling.md`.
- **Secrets / config:** `src/config/envs.ts` valida `PORT` y `APP_NAME` vía `env-var`,
  sin defaults inseguros. `src/.env.template` no contiene valores reales. `src/.env` está
  ignorado por git (`.gitignore:14`) y no aparece en `git ls-files`.
- **Dependencias de producción:** `dotenv`, `env-var`, `express` — superficie mínima.
  `pnpm audit` (con red disponible) solo reporta avisos sobre `qs` (ver `SEC-001`); no
  hay avisos adicionales en `devDependencies`.
